# Trazo ABI v0.1

This ABI defines only the identity of symbols generated by Trazo. It does not yet define a runtime, ownership model, struct layout, or a specific representation for objects.

## Linking Rules

- Standard Trazo functions use mangled names.
- C functions called via `C.name(...)` retain the exact name `name`. 
Trazo does not declare or rename these symbols; they must match a function
that already exists in the imported C headers or libraries.
- Functions declared with `extern "C"` retain their exact name and do not
receive Trazo name mangling.
An `extern "C"` function declaration without a body also emits `extern` in
the generated C; a definition with a body does not emit the redundant
specifier.
- `main` retains the exact name `main` because the C executable requires
that entry point. It is not a Trazo function exported with a public name.
- Mangling is never applied to symbols belonging to the C FFI or to `main`.

## Parameterless Functions

`func name()` means the function receives exactly zero parameters.
Therefore, it is generated as `name(void)` in C. The C form `name()` is avoided
because, in an old-style C declaration, it indicates that parameters are
unspecified, not that the function accepts no parameters.

## Mangling

The initial format is:

```text
trazo_<module>_<name>__<parameter_types>
```

For a function in the root module, `global` is used as the module name:

```trazo
func add(int a, int b) -> int
```

generates the C symbol:

```c
int trazo_global_add__ii(int a, int b);
```

The parameter type codes for v0.1 are:

| Trazo Type | Code |
|---|---|
| `int` | `i` |
| `float` | `f` |
| `char` | `c` |
| `void` | `v` |

`void` is not permitted as a parameter; its code is reserved for future extensions. The return type is not part of the name mangling scheme because it cannot reliably distinguish between overloads: two functions differing only in their return type would result in ambiguous calls.

## Overloading

Two functions may share the same name provided their parameter type lists differ:

```trazo
func print(int value) -> int
func print(float value) -> int
```

produce:

```c
trazo_global_print__i
trazo_global_print__f
```

Call resolution must select the specific signature before generating C code. The code generator must not invent names or resolve overloads based on text matching.

## Identifiers

The module name and function name are normalized to produce valid C identifiers. The v0.1 normalization process replaces any character that is not alphanumeric or an underscore (`_`) with an underscore. The `trazo_` prefix avoids conflicts with reserved C identifiers such as `_T...`.

## Compatibility

This ABI is experimental and is designated as `v0.1`. Changes to the symbol format, type codes, or linking rules require a new ABI version.

The ABI does not guarantee binary compatibility between different versions. At this stage, the compiler must generate all declarations and calls within the same compilation unit.But first, we need to look at the `abi.md` file, which defines Trazo's prototype ABI.
